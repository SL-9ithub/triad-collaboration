# 从人工传递到自动派工

## 两件事要分清

- **技能 = 流程指导。** `triad-collaboration` 技能告诉 C 该怎么分工、写任务单、检查成果。技能文件本身只提供流程指令：它不创建连接，也不授予额外文件权限；派工、读文件、收报告这些动作，是 C 借助当前环境里已有且已获授权的工具完成的。真正提供通道的是连接工具。指令文件和执行它的代理能力是两件事，别混为一谈。
- **连接器 = 实际派工与收报告。** 它才是真正把任务送到执行器、把结果取回来的东西。

本仓库只提供前者：工作流指令、项目级技能（含四类模板）、模拟案例和人工传递步骤。**不含可直接安装的自动连接器**，不会自行登录、创建执行会话、传文件或读取远端成果。

## 目标：让执行花免费额度，判断花主力额度

这套流程的成本目标很清楚：**规划和验收留在主力模型上，执行交给当前可用的低成本或免费执行器。** 对额度紧张的 Plus 用户，这意味着长活可以转移到 W 那侧的可用额度上。但要说完整：C 的派工、读取报告、审阅和返工沟通仍然消耗主力额度，总量是否更省要按实际任务验证，本项目不做固定节省承诺。

要达到的目标状态是：C 写完任务单直接派给 W，W 交回报告与成果，C 自动拿到并检查，不通过就再派一轮——人只在方向、取舍和最终验收上出现。

这个目标现在只能部分成立，原因很直接：

| 环节 | 目标状态 | 实际条件 |
| --- | --- | --- |
| 派工 | C 直接把任务送进 W | 需要你已有一个可用且已获授权的派工工具，并让它对 C 的会话可用 |
| 收报告 | C 自动读回固定报告与成果 | 需要该工具能返回成果位置或正文，且 C 有权读取 |
| 检查与返工 | C 检查后自动开下一轮 | 需要同一通道能再次派发；工具不支持时，仍由人转一次 |
| 免费执行 | 执行转到 W 那侧的可用额度 | 但 C 的派工、读报告、审阅仍消耗主力额度，总量是否更省要按实际任务验证；免费能力随平台和账号当时可用额度变化，本项目不保证长期免费 |

所以：**没有连接时，人工闭环就是当前的正常形态，不是降级凑合。** 连接就位后，C 应直接协调 W，不再让你中转。省额度效果目前没有定量对比数据，别把它当承诺。

## 人工模式怎么跑

L 把 C 的任务单交给独立的 W 会话，再把报告与实际成果交回 C。两个独立会话把“执行”和“检查”分开；C 如果自己补做了成果，必须标明是自查，不能把同一次生成当成独立复核。

人工模式不需要任何配置，代价是 L 要中转消息，并且跨设备时要自己解决文件传递。

## 审阅不止一次

自动派工容易让人以为“一轮派完就该结束”，实际不是：

- 初审发现的问题，需要 W 修订后由 C **复审**，不能凭 W 的“已修正”放行。
- **交付或发布前再复核**关键标准；涉及对外内容时，隐私与准确性单独过一遍。
- 没有真实改动就写“无需改动”，不虚构优化；也不靠固定次数放行，每次结论都要有对应的实际动作。
- 自动通道只减少搬运，不减少检查层数，也不替代 L 的最终决定。

## 分工不重叠

自动或人工，都不改变这条：

- **C 只规划与检查，W 只执行与报告。** C 不代 W 生产成果，W 不代 C 判通过、不代 L 做最终验收。
- W 不可用时的正确降级：C 继续规划、诊断和准备任务单，如实报告阻塞，交 L 决定是等 W 还是改分工。**未经 L 同意，C 不把本该 W 交付的成果自己做完。**
- 若 L 同意由 C 直接执行，成果要标注“C 直接执行”，同时该轮失去独立检查者身份，需要另找检查方或由 L 亲自核对。
- 这条是本项目的分工约定，不是对所有平台能力的断言。换平台先确认它是否支持派工，再决定走自动还是人工。

## 连接器需要提供什么

若你已有获授权的工具，可以按下面的能力约定自行适配。这是能力清单，**不是某个产品的真实 API，也不是可直接运行的命令**。

| 能力 | 输入 | 应返回的信息 |
| --- | --- | --- |
| 提交任务 | 目标项目、请求ID、任务单、成果位置、预算 | 是否接收、执行器任务标识 |
| 查询状态 | 同一请求ID或任务标识 | 未接收、排队、执行中、失败或完成 |
| 读取交付 | 任务标识与报告版本 | 固定报告、实际成果位置、可核对证据 |
| 记录审阅 | 报告版本与 C 的检查结论 | 接受本轮或需新轮修正 |

接入前先确认：工具来源、访问范围、账号授权、目标项目是否一致。技能不授予额外权限，也不假定任何执行器都支持上述接口。

## 可靠性规则

- **请求可识别**：每个新业务轮次一个唯一请求ID。发送结果不确定时，先用原ID查状态，不换ID盲目重投。
- **重复可判断**：同一请求ID重复到达时，执行器应识别为同一轮，返回已有任务标识而不是再执行一次。
- **成果可定位**：报告要能定位到本轮的实际文件与版本。跨设备时先解决经过授权的文件传递。
- **报告固定**：已发布或已固定的报告不原地覆盖；更正另开轮次。有真实的版本摘要工具时可以核对，没有就用轮次和文件版本对齐，不编造哈希或事件ID。
- **失败可恢复**：执行中断时保留已完成的成果、未完成项与续接位置，下一轮从该点继续，不从头重跑也不无限重试。
- **等待有边界**：设置本轮预算（建议 30 至 45 分钟）；到点保存进度并回报，状态未知时先核查，不重复执行外部操作。
- **验收仍由 C 执行**：自动连接不代替独立检查，也不代替 L 的最终决定。

不要通过修改第三方内部数据库、复用他人凭据或跳过认证来模拟官方接口。不同版本、不同设备和冷启动恢复都需要各自实测；本仓库不声称已完成这些适配。

## 分享你自己的适配

写适配说明时，交代清楚：支持的产品版本、使用的公开接口、配置步骤、验证范围、失败恢复方法。示例只用虚构资料，不提交账号凭据、设备路径、真实会话记录或私有运行日志。
